# 展示项目的成本控制约定

2026-11-25用户明确：尽量少消费，主要推到GitHub展示工程能力。保留完整四模态功能目标，优先完成本地可运行、测试、真实小样与README证据。

- 部署以本地Docker为主，云端仅做少量真实联调；不默认购买云服务器、资源包、CDN、加速或云端媒体处理服务。
- TOS采用私有桶、标准存储、默认单AZ（控制台有该项时）；按量进行小文件联调。测试对象使用唯一随机key，仅清理本次创建的对象。
- 测试素材优先自制、无隐私、体积小的文档/图片/短音视频。已有模型小样测试报告保留复用，只有代码/配置变更或新问题需要时再调用。
- CLOUD_BULK_ENABLED保持false；向量、视觉理解、ASR不因浏览页面或自动重试而无上限调用。正式任务的幂等、缓存、重试次数与用量记录仍按设计实现。
- 原计划80项素材的批量云处理、冻结集全量云评测暂缓，先完成自动化离线验收和必要的真实小样；未执行的评测不能写成已通过，也不能编造召回率和业务规模。
- GitHub展示代码、架构图、实际页面截图、可复现测试与已发生的真实联调报告；公开仓库不包含.env、密钥或私人素材。
- 费用报警只作提醒，不当作绝对消费上限。扩大云处理规模或公网部署之前再确定预算和范围。

这是实施约束；本文件不表示尚未实现的限额、缓存与幂等功能已经可用。
